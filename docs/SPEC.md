## 1. 目的

| # | 目的 | 本アプリでの実現方法 |
|---|------|--------------------|
| 1 | 実際の戦闘を模したタイムライン上でスキルを入力する | 仮想時計で進むシミュレーション上で、ボタン/キーボードからアクションを入力する |
| 2 | 正しい順番だけでなく、GCD 停止・アビリティの挟みすぎ・バフずれを判定する | 入力ごとに判定エンジンが「ミス種別＋理由」を記録し、終了後に採点する |
| 3 | 初心者が開幕回しを反復練習できる | ガイド練習モード（次のスキルを提示）とワンボタンのリトライ |
| 4 | スマートフォンと PC の両方で使える | レスポンシブ UI、タップ入力とキーボード入力の両対応 |

## 4. 用語

| 用語 | 定義（本アプリ内） |
|------|------------------|
| GCD | ウェポンスキル等、共通のリキャストタイマー（グローバルクールダウン）を共有するアクション |
| oGCD / アビリティ | GCD を共有しないアクション。GCD の合間に挟む（ウィーブ） |
| リキャスト | アクションを再使用できるまでの時間 |
| チャージ | 複数回ストックできるアクションの残り回数 |
| アニメーションロック | アクション使用後、次のアクションを受け付けない時間 |
| 詠唱 | アクション発動までの入力不可時間（移動は MVP 非対象） |
| ウィーブ | GCD の合間に oGCD を使うこと |
| クリップ | oGCD のアニメーションロックや詠唱により、次の GCD の開始が「GCD が回った時刻」より遅れること |
| GCD 停止（アイドル） | GCD が使用可能なのに何も GCD を押していない時間 |
| コンボ | 直前の特定アクションを条件に効果が変わる GCD の連続 |
| コンボ切れ | コンボ継続条件を満たさずに次段を使った / コンボ受付時間が切れた / 別の GCD で上書きした |
| 仮想時計 | シミュレーション内の時刻（ミリ秒、整数）。t=0 が戦闘開始 |
| お手本（ガイドシーケンス） | 期待される入力の列。開幕回しデータから生成 |
| 入力ログ | `{ t, actionId }` の配列。これを再生すれば同じ結果が再現できる |

## 5. モード

### 5.1 ガイド練習モード

- 常に「次に押すべきスキル」をハイライト表示し、その次の 2〜3 手も小さく表示する。
- 誤ったスキルを押した場合の挙動は設定で選択:
  - **ブロック**（既定）: 誤入力はシミュレーションに反映せず、理由を表示して正しい入力を待つ。時間は進み続ける。
  - **続行**: 誤入力もシミュレーションに反映し、ガイドは再同期（§8.2）を試みる。
- お手本は開幕回しデータ（`OpenerDefinition`）の終わりまで。以降は「お手本なし」で自由入力となる（ループ回しのデータ化は TODO(GAME-40)）。
- 任意設定:「ゆっくりモード」（仮想時計の速度倍率 0.5x / 0.75x / 1.0x）。採点結果には速度倍率を明記する。

### 5.2 自由練習モード

- お手本の提示なし（非表示）。入力は全てシミュレーションに反映。
- ミス理由はリアルタイムに小さく表示（設定でオフ可）。
- 終了後、選択した開幕回しとのずれ・各採点項目を表示する。

### 5.3 共通

- 開始前に 3 秒カウントダウン（§6-1）。
- 途中終了（中断）とリトライ（同条件で即再開始）ボタン。
- 戦闘時間到達で自動終了し結果画面へ。

### 6.1 入力仕様（詳細）

- 1 回の入力 = `{ actionId, source: 'pointer' | 'keyboard', realTime, virtualTime }`。
- 入力が「今すぐ実行可能」ならその時刻に実行。
- 実行できなくても、**そのアクション自身のリキャストの残りが 0.5 秒以下**なら **キュー**（先行入力）し、実行可能になった瞬間に実行する（GAME-05）。
  - 比べるのは、GCD なら GCD の残り、固有のリキャストがある技はその残り（チャージ制は次のチャージまで）。アニメーション硬直と詠唱の残りは条件に入れない。硬直中・詠唱中に押したアビリティは、硬直・詠唱が明けた瞬間に出る。
  - キューは 1 件だけ。**先に押したものが優先**で、キューに入っている間の入力は無視する（同じボタンの押し直しも同じ）。GCD とアビリティを同時にキューすることはできない。
  - キューした入力は、実行する時点でもう一度使えるかを判定し、使えなければ拒否して捨てる（例: その間にコンボが切れた・射程の外に出た）。
  - 地面指定のアクション（抽出データの `targetArea`）はキューしない。
  - 出典（定説。0.5 秒という数値の公式の記述はない）: ゲーム本来のキュー処理を再現したプラグインのコード（ReAction の `QueueAdjustments.cs` の `queueThreshold = 0.5`）、クライアントの解析資料（FFXIVClientStructs の `ActionManager`: キューの欄が 1 組だけ）、キューの入れ替えがプラグインの追加機能として作られていること（ゲーム本来は入れ替えない）、プレイヤーの検証記事。
- それ以外は **拒否** し、拒否理由（リキャスト中、条件未達 等）を記録する。拒否入力は採点で「無効入力」として数える（減点はしない。§7 の設定で変更可）。
- キーボード: `keydown` のみ処理し、`repeat`（押しっぱなし）は無視する。押しっぱなしでは連打にならない（実機の挙動は不確か: GAME-05）。
- スマートフォン: `pointerdown` で即時発火（`click` の遅延を避ける）。ダブルタップズーム抑止（`touch-action: manipulation`）。

### 6.1a 光る条件（ハイライト）

ホットバーのアクションが光る（点線の枠が回る）条件は、**ゲームデータに基づく 2 つだけ**とする。推測で条件を足さない。

| 条件 | ゲームデータ | 侍の例 |
|------|-------------|--------|
| コンボ | Action の `ActionCombo`（抽出データの `comboFrom`）。直前のコンボ技を受付時間内に使っていれば、その次の技が光る | 暁風の後の陣風・士風・雪風、陣風の後の月光 |
| 発動条件のステータス | Action の `ActionProcStatus`（抽出データの `actionProcStatus`、指すステータスは `actionProcStatusId`）。そのステータスが付いている間光る | 燕飛（燕飛効果アップ）、返し五剣・返し雪月花・天道返し五剣・天道返し雪月花（燕返し実行可）、奥義波切（奥義波切実行可）、残心（残心実行可） |

- 上のどちらにも当たらないもの（居合術の変化先、照破、明鏡止水中のコンボ技、返し波切）は光らせない。明鏡止水中に特別な光り方があるかはゲーム内で要確認（GAME-18）。
- 使えない状態（剣気不足など）の暗い表示と、光る表示は別に扱う（両方同時に付くことがある）。

### 6.2 時間モデル

- シミュレーションは **仮想時計（整数ミリ秒）** による決定的（deterministic）処理とする。
- UI は `requestAnimationFrame` で実時間差分を仮想時計に変換して `tick(now)` を呼ぶだけ。ロジックは持たない。
- 同じ「練習設定 + 入力ログ」からは常に同じ結果が再現される（テスト容易性と共有のため）。
- タブが非アクティブになった場合は自動で一時停止する（`visibilitychange`）。一時停止があった試行は結果に明記する。
- GCD の長さは、そのアクションのリキャスト（`recast`。ルビー・リチュアルなら 3 秒、エメラルド・リチュアルなら 1.5 秒）。固有のリキャストタイマーを持つ GCD（召喚士のサモン・バハムート: 60 秒）は、固有のタイマーとは別に共通の GCD を 2.5 秒回す（説明文「この魔法は固有のリキャストタイマーを持つ」）。

### 6.3 通信遅延・アニメーションロックの扱い

- アニメーションロック（硬直）の長さはサーバーが送ってくる値で、クライアントのデータにない（GAME-04）。コミュニティの解析（定説）から、次の値を仮に置く。
  - 詠唱のない技: **0.6 秒＋応答の遅れ**。応答の遅れ（サーバーまでの往復と処理）は設定で変えられる（既定 50ms。0 / 50 / 100 / 150ms）。
  - 詠唱のある技: 詠唱中は硬直なし。詠唱完了の後に **0.1 秒**（応答の遅れは足さない）。
  - 例外: 侍の必殺剣・夜天（後ろへ飛び退く）は 0.8 秒。必殺剣・暁天は 0.6 秒と 0.8 秒の説があり、0.6 秒にしている。
  - 出典: xiv.dev の animation-lock の解説、ffxiv_bossmod の `AnimationLockTweak.cs`・`ActionDefinition.cs`（詠唱後 `CastAnimLock 0.1`、夜天 `animLock=0.800`）。
- 移動を伴う技は、説明文から読んで練習場の自分を動かす（移動にかかる時間は省き、残像を出す）。「対象に急接近」= 敵の当たり判定の外側 1m まで、「N m後方へ（に）飛び退く」= 敵から離れる向きに N m、「自身の N m前方に向かって素早く移動」= 向いている方へ N m（エーテリアルシフト）、「対象の目前まで素早く移動」= ターゲットした相方の 1m 手前（エーテリアルステップ）、「黒魔紋の中心へ素早く移動」= 黒魔紋の中心（ラインズステップ）。
- 実際のゲームは「使えるようになった次のフレーム」で出るため、フレームレートが低いほど遅れる。練習ではフレームの遅れを入れない。

### 6.4 詠唱と滑り撃ち

- 詠唱の残りが **猶予より多い**うちに動く（ジャンプを含む）と、詠唱は中断される。猶予は既定で **詠唱 1.39 秒以上は 0.66 秒、それより短い詠唱は 0.54 秒**（実測）。設定で「安全側」（0.5 秒）にできる。中断すると効果は出ず、GCD のリキャストは戻る（すぐ次を使える）。
- 残りが猶予を切ってからは、動いても詠唱は完了する（**滑り撃ち**）。効果（与ダメージ上昇の計算）はこの時点で決まり、以後は戦闘不能になっても完了する。ダメージの表示は詠唱完了の時点。
  - 理由: サーバーは詠唱終了の約 0.5 秒前に行動を確定して結果を送り、それを受け取った後は詠唱を取り消せない（FFXIVClientStructs の `CastInfo`）。
  - 実測（Lodestone の検証。利用者が提供）: キャストバーを録画してコマ送りし、詠唱に成功した最も早い移動と失敗した最も遅い移動を調べたもの。詠唱 1.39〜3.55 秒では残り 0.66 秒以下で成功し、詠唱時間が違ってもほぼ一定。詠唱 0.98 秒（エスナを短くしたもの）では残り 0.54 秒以下で確実に成功。別の条件では残り 0.44 秒で失敗した例もあり、境界は固定ではない（通信の遅れによると考えられる）。
  - ほかに「0.46＋0.02×詠唱時間」という実測もある（xivintheshell）。練習の既定は上の実測の値にし、失敗した例に備えて安全側（0.5 秒）も選べるようにする（GAME-55）。
- 移動中に詠唱のある技を押すと、詠唱は始まり、すぐに中断される。「移動中は詠唱できません」のようなエラー文は見つからず、「始まってから中断される」という記述があるため（不確か: GAME-55）。
- GCD のリキャストは詠唱の開始から回る。詠唱時間がリキャスト以上の技（レイズなど）は、次の GCD が詠唱完了＋0.1 秒の後になる（キャスターの 0.1 秒）。
- 侍の居合術と奥義波切の詠唱は、Lv100 では 1.3 秒（Lv74 の特性「居合術効果アップ」。風花では短くならない）。抽出データの詠唱時間（1.8 秒）は特性の前の値。特性の説明文は未抽出のため仮（GAME-64）。

## 7. 採点

### 7.1 採点項目

各項目は 0〜100 点で算出し、重み付き平均を総合点とする。重みは `ScoringProfile`（データファイル）で定義。
全ての判定は入力ログの再シミュレーション結果（イベント列）から算出する。

| 項目 ID | 項目 | 定義 | 算出式（案） |
|---------|------|------|-------------|
| `gcdUptime` | GCD 稼働率 | 戦闘時間のうち、GCD がリキャスト中・詠唱中だった時間の割合 | `1 - idleMs / evaluatedMs`。`idleMs` = GCD 使用可能になってから次の GCD を開始するまでの合計。最初の GCD 前の時間の扱いは設定（既定: t=0 から計測） |
| `sequence` | 正しいスキル順 | お手本シーケンスとの一致度 | 実行済みアクション列とお手本列の最長共通部分列（LCS）長 / お手本長。GCD と oGCD は別に計算しても表示する |
| `comboBreaks` | コンボ切れ | コンボ継続に失敗した回数 | `max(0, 100 - 回数 × penalty)`。原因（時間切れ / 別 GCD で上書き / 前段なし）を内訳表示 |
| `clipping` | アビリティ挟みすぎによるクリップ | oGCD のロックにより GCD 開始が遅れた合計時間と回数 | `clipMs` = Σ max(0, 次GCD開始 - GCD使用可能時刻)（その区間で oGCD/ロックが原因のもの）。点数は `clipMs` に対する閾値テーブルで算出 |
| `statusUptime` | バフ・DoT の維持 | 維持対象ステータス（データで指定）の稼働率と、切らした回数・早すぎる上書き回数 | 対象ごとに `activeMs / (evaluatedMs - 付与可能になるまでの時間)`。早期上書きは残り時間の無駄（ms）として別集計 |
| `overcap` | リソースあふれ | ゲージ上限超過量・チャージが最大のまま放置した時間・同じフラグの重複付与 | ゲージ: 捨てた量の合計。チャージ: 最大チャージ到達後の経過時間合計 |
| `keyActions` | 主要アクションの使用回数 | データで指定した主要アクションの使用回数 vs 期待回数 | `min(1, 実回数/期待回数)` の平均。期待回数はデータで明示するか、リキャストから理論最大回数を算出（TODO(GAME-41)：理論最大の算出条件） |
| `openerDeviation` | 開幕回しからのずれ | 開幕回しの各ステップの順序ずれと時刻ずれ | 順序: 最初に一致しなくなったステップ番号。時刻: 各ステップの `実時刻 - お手本時刻` の絶対値平均（お手本時刻は理想シミュレーションから算出） |

> 判定しきい値（何 ms 以上をクリップとみなすか、トリプルウィーブ判定など）は **ゲーム仕様ではなくアプリの採点ポリシー** であり、`ScoringProfile` に初期値を置いて調整可能にする。初期値は実装時に決め、根拠を記載する。

## 8. ガイドシーケンス

### 8.1 生成

- `OpenerDefinition` の `steps`（アクション ID の列、任意でプリプル時刻指定）をそのままお手本とする。
- 各ステップの **お手本時刻** は、同じエンジンで「最速入力（使用可能になった瞬間に押す）」をシミュレーションして算出する（手入力しない）。

### 8.2 再同期（続行モード・自由モードのずれ計算）

- 実行されたアクションがお手本の現在ステップと異なる場合、先読みウィンドウ（既定 3 手）内に一致するステップがあればそこへ進める。無ければステップを進めない。
- 採点の `sequence` は再同期ではなく LCS で算出するため、再同期ロジックの影響を受けない。
