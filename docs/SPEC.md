## 1. 目的

| # | 目的 | 本アプリでの実現方法 |
|---|------|--------------------|
| 1 | 実際の戦闘を模したタイムライン上でスキルを入力する | 仮想時計で進むシミュレーション上で、ボタン/キーボードからアクションを入力する |
| 2 | 正しい順番だけでなく、GCD 停止・アビリティの挟みすぎ・バフずれを判定する | 入力ごとに判定エンジンが「ミス種別＋理由」を記録し、終了後に採点する |
| 3 | 初心者が開幕回しを反復練習できる | ガイド練習モード（次のスキルを提示）とワンボタンのリトライ |
| 4 | スマートフォンと PC の両方で使える | レスポンシブ UI、タップ入力とキーボード入力の両対応 |

## 4. 用語

| 用語 | 定義（本アプリ内） |
|------|------------------|
| GCD | ウェポンスキル等、共通のリキャストタイマー（グローバルクールダウン）を共有するアクション |
| oGCD / アビリティ | GCD を共有しないアクション。GCD の合間に挟む（ウィーブ） |
| リキャスト | アクションを再使用できるまでの時間 |
| チャージ | 複数回ストックできるアクションの残り回数 |
| アニメーションロック | アクション使用後、次のアクションを受け付けない時間 |
| 詠唱 | アクション発動までの入力不可時間（移動は MVP 非対象） |
| ウィーブ | GCD の合間に oGCD を使うこと |
| クリップ | oGCD のアニメーションロックや詠唱により、次の GCD の開始が「GCD が回った時刻」より遅れること |
| GCD 停止（アイドル） | GCD が使用可能なのに何も GCD を押していない時間 |
| コンボ | 直前の特定アクションを条件に効果が変わる GCD の連続 |
| コンボ切れ | コンボ継続条件を満たさずに次段を使った / コンボ受付時間が切れた / 別の GCD で上書きした |
| 仮想時計 | シミュレーション内の時刻（ミリ秒、整数）。t=0 が戦闘開始 |
| お手本（ガイドシーケンス） | 期待される入力の列。開幕回しデータから生成 |
| 入力ログ | `{ t, actionId }` の配列。これを再生すれば同じ結果が再現できる |

## 5. モード

### 5.1 ガイド練習モード

- 常に「次に押すべきスキル」をハイライト表示し、その次の 2〜3 手も小さく表示する。
- 誤ったスキルを押した場合の挙動は設定で選択:
  - **ブロック**（既定）: 誤入力はシミュレーションに反映せず、理由を表示して正しい入力を待つ。時間は進み続ける。
  - **続行**: 誤入力もシミュレーションに反映し、ガイドは再同期（§8.2）を試みる。
- お手本は開幕回しデータ（`OpenerDefinition`）の終わりまで。以降は「お手本なし」で自由入力となる（ループ回しのデータ化は TODO(GAME-40)）。
- 任意設定:「ゆっくりモード」（仮想時計の速度倍率 0.5x / 0.75x / 1.0x）。採点結果には速度倍率を明記する。

### 5.2 自由練習モード

- お手本の提示なし（非表示）。入力は全てシミュレーションに反映。
- ミス理由はリアルタイムに小さく表示（設定でオフ可）。
- 終了後、選択した開幕回しとのずれ・各採点項目を表示する。

### 5.3 共通

- 開始前に 3 秒カウントダウン（§6-1）。
- 途中終了（中断）とリトライ（同条件で即再開始）ボタン。
- 戦闘時間到達で自動終了し結果画面へ。

### 6.1 入力仕様（詳細）

- 1 回の入力 = `{ actionId, source: 'pointer' | 'keyboard', realTime, virtualTime }`。
- 入力が「今すぐ実行可能」ならその時刻に実行。
- 実行不可だが先行入力受付時間内であれば **キュー**（1 件のみ保持、後勝ち）し、実行可能になった瞬間に実行。
- それ以外は **拒否** し、拒否理由（リキャスト中、条件未達 等）を記録する。拒否入力は採点で「無効入力」として数える（減点はしない。§7 の設定で変更可）。
- キーボード: `keydown` のみ処理、`repeat` イベントはキュー更新として扱う。
- スマートフォン: `pointerdown` で即時発火（`click` の遅延を避ける）。ダブルタップズーム抑止（`touch-action: manipulation`）。

### 6.2 時間モデル

- シミュレーションは **仮想時計（整数ミリ秒）** による決定的（deterministic）処理とする。
- UI は `requestAnimationFrame` で実時間差分を仮想時計に変換して `tick(now)` を呼ぶだけ。ロジックは持たない。
- 同じ「練習設定 + 入力ログ」からは常に同じ結果が再現される（テスト容易性と共有のため）。
- タブが非アクティブになった場合は自動で一時停止する（`visibilitychange`）。一時停止があった試行は結果に明記する。

### 6.3 通信遅延・アニメーションロックの扱い

- 実ゲームのアニメーションロックやサーバー往復遅延はプレイヤー環境で異なるため、**設定値**（既定値はデータから、ユーザーが上書き可）として扱う。
- 既定値は TODO(GAME-04)。確認できるまでは「未検証」表示を出す。

## 7. 採点

### 7.1 採点項目

各項目は 0〜100 点で算出し、重み付き平均を総合点とする。重みは `ScoringProfile`（データファイル）で定義。
全ての判定は入力ログの再シミュレーション結果（イベント列）から算出する。

| 項目 ID | 項目 | 定義 | 算出式（案） |
|---------|------|------|-------------|
| `gcdUptime` | GCD 稼働率 | 戦闘時間のうち、GCD がリキャスト中・詠唱中だった時間の割合 | `1 - idleMs / evaluatedMs`。`idleMs` = GCD 使用可能になってから次の GCD を開始するまでの合計。最初の GCD 前の時間の扱いは設定（既定: t=0 から計測） |
| `sequence` | 正しいスキル順 | お手本シーケンスとの一致度 | 実行済みアクション列とお手本列の最長共通部分列（LCS）長 / お手本長。GCD と oGCD は別に計算しても表示する |
| `comboBreaks` | コンボ切れ | コンボ継続に失敗した回数 | `max(0, 100 - 回数 × penalty)`。原因（時間切れ / 別 GCD で上書き / 前段なし）を内訳表示 |
| `clipping` | アビリティ挟みすぎによるクリップ | oGCD のロックにより GCD 開始が遅れた合計時間と回数 | `clipMs` = Σ max(0, 次GCD開始 - GCD使用可能時刻)（その区間で oGCD/ロックが原因のもの）。点数は `clipMs` に対する閾値テーブルで算出 |
| `statusUptime` | バフ・DoT の維持 | 維持対象ステータス（データで指定）の稼働率と、切らした回数・早すぎる上書き回数 | 対象ごとに `activeMs / (evaluatedMs - 付与可能になるまでの時間)`。早期上書きは残り時間の無駄（ms）として別集計 |
| `overcap` | リソースあふれ | ゲージ上限超過量・チャージが最大のまま放置した時間・同じフラグの重複付与 | ゲージ: 捨てた量の合計。チャージ: 最大チャージ到達後の経過時間合計 |
| `keyActions` | 主要アクションの使用回数 | データで指定した主要アクションの使用回数 vs 期待回数 | `min(1, 実回数/期待回数)` の平均。期待回数はデータで明示するか、リキャストから理論最大回数を算出（TODO(GAME-41)：理論最大の算出条件） |
| `openerDeviation` | 開幕回しからのずれ | 開幕回しの各ステップの順序ずれと時刻ずれ | 順序: 最初に一致しなくなったステップ番号。時刻: 各ステップの `実時刻 - お手本時刻` の絶対値平均（お手本時刻は理想シミュレーションから算出） |

> 判定しきい値（何 ms 以上をクリップとみなすか、トリプルウィーブ判定など）は **ゲーム仕様ではなくアプリの採点ポリシー** であり、`ScoringProfile` に初期値を置いて調整可能にする。初期値は実装時に決め、根拠を記載する。

## 8. ガイドシーケンス

### 8.1 生成

- `OpenerDefinition` の `steps`（アクション ID の列、任意でプリプル時刻指定）をそのままお手本とする。
- 各ステップの **お手本時刻** は、同じエンジンで「最速入力（使用可能になった瞬間に押す）」をシミュレーションして算出する（手入力しない）。

### 8.2 再同期（続行モード・自由モードのずれ計算）

- 実行されたアクションがお手本の現在ステップと異なる場合、先読みウィンドウ（既定 3 手）内に一致するステップがあればそこへ進める。無ければステップを進めない。
- 採点の `sequence` は再同期ではなく LCS で算出するため、再同期ロジックの影響を受けない。
