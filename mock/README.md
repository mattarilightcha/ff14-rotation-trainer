# UI モック（侍 Lv100 木人練習）

FF14 の HUD に寄せた見た目と操作感を試すための、単独で動くモックです。本実装（React / TypeScript）の前に、見た目と操作感を確かめるためのものです。

## 開き方

`mock/index.html` をブラウザで開くだけで動きます（サーバー不要。`../public/icons/` のアイコンを参照するので、リポジトリの中で開いてください）。

| 操作 | キー |
|------|------|
| 開始（3 秒カウントダウン） | `Space` / パッドの Start |
| リセット | `Esc` |
| ホットバー 1 / 2 / 3 | `1`〜`0` `-` `=` / `Shift` + 同じキー / `Alt` + 同じキー |
| クロスホットバー（パッド） | LT/RT を押しながら十字キー・ABXY（右上のボタンで表示を切り替え） |
| 説明文を見る | アイコンにマウスを乗せる |
| 共有 / ジョブ専用の切り替え | ホットバー左の `HB5 共` などのラベルをクリック |
| アクションの変化の設定 | 右上の「アクションの変化…」（居合術・燕返し・奥義波切を「変化させない（別ボタン）」にできる） |
| クロスホットバーのセット切り替え | パッド表示の上のタブ / パッドの RB（仮） |

`Ctrl` + 数字はブラウザのタブ切り替えと衝突するため使いません（INPUT_HUD §3）。

## 主な機能

| 機能 | 内容 |
|------|------|
| ゲームモード | 開始画面の「ゲームモードで開始」、または上の「ゲームモード」。全画面にして、Chrome / Edge ではキーボードロックで Ctrl+W・Ctrl+数字・F5・Alt などもゲーム側で受け取る。解除は Esc の長押し。練習中にページを閉じようとすると確認が出る |
| 光る枠 | ゲームデータ（コンボ条件と ActionProcStatus）に基づく（docs/SPEC.md §6.1a） |
| 演出 | 手描き SVG の木人（叩くと揺れる・光る）、範囲の形（抽出データの castType）ごとのヒットエフェクト、居合術の詠唱の光、フライテキスト、夜の稽古場の背景と花びら。動きを減らす OS 設定では控えめになる |
| 効果音 | Web Audio でその場で合成（ゲームの音声は使わない）。上の「音」で入/切、「設定ファイルを読み込む…」の中で音量 |
| 結果 | 仮の採点とランク、GCD・止まり・クリップ・アビリティ・風月/風花/彼岸花のタイムライン、使用回数 |
| 動作確認用 | URL に `?speed=4` のように付けると時間が速く進む |

## 中身

| ファイル | 内容 |
|---------|------|
| `sam-hotbar-sample.json` | サンプルの `HOTBAR.DAT` から、侍のセット（34）と共有のセット（0）のアクション ID と種類だけを取り出したもの（docs/CONFIG_FORMAT.md §2） |
| `build-mock-data.mjs` | 第 1 層（`src/data/ffxiv/*.json`）から侍 Lv100 の分を取り出し、`mock-data.js` を作る。`node mock/build-mock-data.mjs` |
| `mock-data.js` | 自動生成（手で編集しない） |
| `fx.js` / `audio.js` / `gamemode.js` | 演出 / 効果音 / ゲームモード |
| `mock.js` | 判定の簡易版。名称・詠唱・リキャスト・コンボ元は抽出データから、剣気・閃・バフの動きはツールチップの記述から（出典をコメントに記載）。ゲームデータにない値は `POLICY`（仮）にまとめている |

## モックの割り切り（本実装とは違うところ）

- アニメーションロック 0.6 秒、先行入力 0.5 秒、コンボ受付 30 秒、剣気の上限 100 は**仮の値**（GAME-04〜06, 12）。
- 黙想は、剣圧を即座に 3 にする簡易版。プリプルで使えるのは明鏡止水とトゥルーノースだけ（GAME-30 未確認のため）。
- クロスホットバーのスロット番号とボタンの対応は仮（CFG 未確認）。
- どのバーが共有かは推定（CFG-08）。アクションの変化の設定も推定＋手動（CFG-11）。
- ホットバー 5〜10 はキー割り当てが未解読（KEYBIND.DAT）のため、クリックでのみ使える。
- 採点は一部の項目だけ。お手本（開幕回し）と一時停止は未実装。
- 判定は `requestAnimationFrame` の中で行っており、本実装の「決定的なエンジン」（STATE_MACHINE.md）ではない。

## サーバー（nettoge.com）に仮で置く

`.github/workflows/deploy-mock.yml` が、`mock/` などを変更して push したとき（または Actions 画面で「Run workflow」を押したとき）に動きます。

1. **必ず作られるもの:** Actions の実行結果ページの下にある成果物 **`mock-site`**（zip）。中身をサーバーの好きな場所にアップロードすれば、そのまま動きます（`index.html` を開くだけ。サーバー側の設定は不要）。
2. **自動でサーバーへ送る場合:** GitHub のリポジトリ設定 → **Settings → Environments → New environment** で `mock` を作り、次を登録します（値はチャットやコードに書かないでください）。

| 種類 | 名前 | 内容 |
|------|------|------|
| Secret | `DEPLOY_HOST` | サーバーのホスト名または IP |
| Secret | `DEPLOY_PORT` | SSH のポート（22 なら省略可） |
| Secret | `DEPLOY_USER` | アップロード用のユーザー |
| Secret | `DEPLOY_SSH_KEY` | そのユーザーの秘密鍵（アップロード専用に作った鍵を推奨） |
| Secret | `DEPLOY_KNOWN_HOSTS` | `ssh-keyscan -p <ポート> <ホスト>` の出力（指紋を確認したもの） |
| Variable | `DEPLOY_MOCK_PATH` | 置き場所のフォルダ（例 `/var/www/html/tools/ff14-rotation-trainer-mock`）。**中身は毎回入れ替わる**ので専用のフォルダにする |
| Variable | `MOCK_URL` | 公開 URL（例 `https://nettoge.com/tools/ff14-rotation-trainer-mock/`）。送信後の確認に使う（省略可） |

- Secrets が未登録のときは、送信を省略して警告を出すだけです（zip は作られます）。
- 仮の公開なので、`noindex` と `robots.txt` で検索エンジンに載らないようにしています。
- SSH を特定の IP に制限している場合、GitHub Actions からは接続できないことがあります（docs/DEPLOY.md §4.3）。そのときは zip を手でアップロードしてください。
